# 01 需求与验收

员工需要确认公司制度和产品 FAQ，输入问题及可选历史，得到有原文出处的回答；遇到冲突或缺失时知道还需确认什么。题号 3，依据用户提供的项目要求截图确认。所有知识源为合成演示材料，不代表真实公司规定。

初始范围为 Python CLI、一个原生工具调用 Agent、本地 JSON 和 BM25。用户随后明确增加本机可视化验收与页面输入 DeepSeek API Key 的需求，现已提供 `serve` 页面，复用相同执行器。部署、多 Agent、独立向量数据库不在范围内。没有使用 LangGraph 或其他 Agent 框架。

## 成功标准

真实模型每轮根据当前上下文选择工具或结束；程序执行并反馈工具结果。不能用业务 if/else、固定检索流水线或脚本 Trace 代替真实模型决策。无可用模型时允许交付离线工程验证，但真实效果必须 BLOCKED，不能宣称整体完成真实验收。

回答须包含 status、answer、claims、citations、conflicts、knowledge_gaps、clarification_question、stop_reason、run_id。制度性结论有 claim 到 citation 对应；原文必须在本次成功读取中出现。冲突须查找明示适用/替代关系，仍无依据则列出双方并澄清，不能以日期或分数裁决。

## 六项必需验收

| 验收点 | 用例 | 预期 | 当前证据边界 |
|---|---|---|---|
| 明确答案 | E01 | 无冲突语料，费用发生后 30 天内提交，引用 D01 | Mock 工程 PASS；已有网页 Live 一条，经AI证据复核，候选人仍需确认 |
| 文档冲突 | E02 | D01 30 天、D02 15 天及双方原文；查证后追问 | Mock 工程 PASS，live BLOCKED |
| 资料外问题 | E03 | 育儿假资料缺失，不编造 | Mock 工程 PASS，live BLOCKED |
| 相似改写 | E04 | 口语提问仍得到 30 天及原文 | 仅脚本流程 PASS，真实理解 BLOCKED |
| 上下文追问 | E05 | 从历史识别报销主题并重新读取依据 | 历史传递 PASS，真实指代理解 BLOCKED |
| 工具失败 | E06 / E07 | 观察错误后的实际后续模型动作或明确失败 | Mock 反馈/终止 PASS，live 决策 BLOCKED |

## 额外完整性验证

E08 以持续请求工具的 Mock 检查预算；E09 保持问题不变，将原文期限替换为 45 天并重新加载；E10 保持实现不变，在 E01 的无冲突版本加入 D02。预期在 [evaluation_cases.json](../data/evaluation_cases.json) 中先于批量运行定义，不把用例编号传入 live 模型。

范围还包括空查询/无命中、工具参数错误、原文读取错误、引用修复、预算计数（含失败和批量）、模型/网络错误、运行目录隔离、按事件写 Trace、输入/语料校验和安装后的包入口。具体实际结果见 [评估](03-evaluation.md)。

候选人个人贡献、总投入和提交 URL/SHA 必须按本人事实填写，目前均不能由 AI 代认。题号已由截图确认，不能由此推断其他个人信息或成绩。
